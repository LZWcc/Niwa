# 开发说明

给想改代码、参与开发的人看；给用户看的介绍在 [README](../README.md)。

使用 WXT + React + TypeScript 开发的轻量浏览器新标签页：左上角时间与节气，正中搜索框，下面是快捷方式和小组件自由摆放的网格，背景是随季节、时辰变化的山水（深色时是月夜）。右上角可以切换浅色 / 深色（日落月升的过渡，默认跟随系统）；旁边的设置面板集中了各处的设置，也可以在那里把全部数据导出成备份，在另一个浏览器里导入。

## 开发

```sh
pnpm install
pnpm dev -b edge
```

在自动打开的开发浏览器中按 `⌘T`（Windows/Linux 使用 `Ctrl+T`）查看新标签页；如果浏览器询问是否保留新标签页更改，选择保留。保存源码后 WXT 会热更新或重载扩展。

本机浏览器路径在 `web-ext.config.ts` 中配置，该文件被 Git 忽略。`pnpm dev` 默认编译 Chrome 目标，`pnpm dev -b edge` 编译 Edge 目标。

提交前运行：

```sh
pnpm check   # 类型检查 + ESLint + Prettier 格式检查
pnpm test    # 布局算法单元测试 + 页面测试
```

`pnpm format` 按 Prettier 格式化全部文件。

## 节气与月相

左上角日期后面是节气和候（`utils/almanac.ts`，起始日期取公历近似值，误差约 ±1 天）。下面一行小字是这一候在元代吴澄《月令七十二候集解》里的解释（`utils/pentads.ts`）：每候从原文里摘一段连续的原文（不改字），悬停看这一候的完整原文。原文取自维基文库，繁体转简体后人工修正了几处：「閒」作「间」，「坏（pī）」作「坯」，扩展区的「𫛪」写回「鴽」，清代避讳的「元鸟」复原为「玄鸟」，几个异体字。72 个候名是类型 `Pentad`，节气表里的每一候都必须有解释，少了 tsc 会报错。

夜庭里的月亮按当天的真实月相画（浅色「山水」里那个圆是太阳，不管几点都是整圆）：`moonPhase` 按平均朔望月推算（和实际朔望时刻差不到半天），`moonPath` 画出亮着的那部分（一侧月面半圆加明暗交界的半个椭圆），`applyAtmosphere` 每分钟把它写成 `--moon-mask`、亮着的比例写成 `--moon-lit`；暗面留一点很淡的轮廓，光晕随亮面变弱。开发时可以用 `?moon=0.25`（0 新月、0.5 满月）预览。

## 搜索

搜索框是原生表单提交（GET 到 `config.ts` 里搜索引擎的地址），页面任意处按 `/` 聚焦。

输入时在收藏夹和浏览记录里找，列在搜索框下面（`useSuggestions`，只读本地数据，不联网）：收藏排在前面（最多一半），浏览记录按访问次数排，同一个网址只留一条，最多 6 条。↓↑ 选择（走过两头回到输入框），回车打开选中的，⌘ / Ctrl + 回车在新标签页打开；没选中时回车照常搜索。Esc 只收起联想、不清空输入框。读取用的是收藏夹、历史小组件申请过的权限；都没有时联想里问一次「允许 / 不用了」。

引擎菜单（搜索框左边）里可以关掉联想（`niwa:search-suggest`，「不用了」也是关掉它），以及管理**排除的网站**（`niwa:search-exclude`）：排除按域名、含子域名，只影响联想，不动浏览器的收藏和历史；在联想里悬停一条、点右侧的 × 也能排除它所在的网站。排除列表本身会暴露不想被看到的网站，所以算私密信息（见「备份与恢复」）。

## 网格

网站快捷方式和小组件存在同一个列表里（`niwa:grid`），每一项记自己左上角的列 x、行 y，可以留空、竖着叠。网格单位 80px、间距 20px，最多 12 列（1180px，搜索框固定 716px）；快捷方式 1×1（图标 58px），小组件小 2×2、中 4×2、大 4×4。

数据流：`useGrid`（存什么）→ `useGridLayout`（结合当前列数算出每一格在哪）→ `Grid` 画出来；拖动由 `useGridDrag` 处理，增删、改尺寸、拖动都经过 `useFlip` 的 `animate`，其余格子会滑到新位置。

- 「添加」也是一个能拖的格子，位置存在 `niwa:add`，第一次打开时放在最后一格后面。新加的格子：「添加」排在最后时占它的位置、它往后挪一格；否则接在最后一格后面，不填前面留的空。
- 没有位置的项（第一次打开时的默认项）按顺序补进空位并保存；窗口变窄、某一格超出列数时临时挪到空位里，不改保存的位置。
- 页面打开期间不移动 DOM 节点，位置全靠 `grid-column` / `grid-row`（移动节点会让毛玻璃重建合成层、闪一下）。

拖放规则在 `utils/grid/layout.ts`。拖 1×1 的格子（快捷方式、文件夹、「添加」）参照手机桌面（`insertIcon`）：

- 落点是指针所在的格子：空格子直接放下；有别的 1×1 就插进去，从那里往被拖那块原来的格子那边按阅读顺序一个个顺移一格，碰到第一个空格子就停（远处的不动），被组件盖住的格子跳过；组件盖住的格子不接受。
- 总是从拖动开始时的摆放算，拖回原处就复原。指针停稳（慢于 0.15 像素/毫秒持续 0.2 秒）才让位，划过、减速经过的格子都不动；没停稳就松手，照常插到指针所在的格子。

拖小组件参照 react-grid-layout / gridstack，只有四条（`moveItem`）：

1. 拖到空位：直接放下；
2. 压到同尺寸的（压住一半以上）：两块互换；大的压到几个小的：这几个保持相互位置整组搬进它腾出来的地方；
3. 搬不进去时：小的竖直往下推，下面碰到的也依次往下推，从不横向绕行（`pushDown`，改尺寸变大也用它）；
4. 小的压到大的：不接受，留在上一个有效位置。

拖动时从上一次判断到的格子一格一格走到当前格子（`stepDrag`），先让开路上的小图标，再碰到后面的组件；互换和整组搬移会累积。交互细节在 `hooks/grid/useGridDrag.ts` 开头：按住移动超过 4px 才算拖动，小组件的落点是左上角吸附到的格子（挪过半格就到下一格），指针移动很快时先不定落点，拖动期间列数锁定，按 Esc 恢复。

收纳文件夹（参照 Launchpad 和手机桌面）：

- 网格里多一种 `folder`（`FolderItem`）：占一格，里面按顺序放几个快捷方式（不记位置，还是原来的 id，图标图片不用搬）。图标是前四个的缩略图（`Folder.tsx`）。至少两个：只剩一个时换回那个快捷方式，放在文件夹的位置（移出、拖出、删除都一样）。
- 合成：拖着快捷方式停在另一个快捷方式或文件夹的图标正中（离中心 26px 以内，差不多是整个图标）时永远不让位；停 0.4 秒，目标放大高亮，这时松手就放进去（快捷方式上新建文件夹、它在前，文件夹上加到最后）。新建的文件夹马上打开、选中名字，直接打字改。没停够就松手，照常插到那一格；经过图标边上时没停稳不会让位，可以从边上滑到正中。细节在 `useGridDrag.ts` 开头。
- 打开（`FolderPanel.tsx`）：点一下或右键。名字点一下就能改；里面的快捷方式和网格上的一样，点了照常打开网站，右键编辑（没有悬停出现的编辑按钮），编辑框里多一个「移出文件夹」；底下可以解散（第一个放在文件夹的位置，其余依次放进后面的空格子）。
- 在面板里拖动换顺序（`useFolderDrag.ts`），和网格一样停稳才换，没停稳就松手照常插到指针所在的格子；拖出面板就放到指针下的格子（有东西就往后找空的），关上面板，交给网格的 `useGridDrag` 的 `start` 接着拖，松手照常按上面的规则落下。

## 小组件

同一种小组件可以放多个，各管各的：每个小组件自己的设置和数据放在网格这一项的 `settings` 里（`WidgetSettings`），只有网格一个地方读写，不会两个小组件互相覆盖；备份、移除都跟着这一项走。日程的日历、庭的天数、和风的 KEY 是共用的。页面级的事（任意处粘贴存便签、背景跟随天气）只由同一种里最靠左上的那个接管（`first`）。

- **便签**（`widgets/notes/`）：回车保存，点一条复制；焦点不在输入框时在页面任意处粘贴会直接存成一条（放了几个便签时存进最靠左上的那个）。每个便签是独立的一组（`settings.notes`）；里面有内容时，“移除小组件”要点两次（第一次提醒会连同几条便签一起删掉，关掉菜单就取消，`WidgetFrame` 的 `losing`）。
- **日程**（`widgets/calendar/`）：粘贴 Google 日历的「iCal 格式的私密地址」（或任意 .ics 订阅地址），只读、无需登录，可以连接多个日历。也可以**导入 .ics 文件**（拖进「管理日历」、拖到卡片上，或选择文件，可以一次多个）：给没有订阅地址的课程表、节假日、从别的日历导出的用；是一份快照，不会自动更新，源文件变了再导入一次，同名的替换内容。文件内容存在 IndexedDB（`utils/calendar/files.ts`，每个最大 5MB，localStorage 放不下），日历列表里这种日历的 url 是 `file:<随机串>`，每次导入换一个，缓存跟着失效；移除日历时文件一起删掉。`CalendarWidget` 负责数据、菜单和两个对话框；`CalendarAgenda` 列出接下来 7 天，按实际高度放得下几条显示几条，不出滚动条；`CalendarMonth` 是月历（点标题这一行、日期面板或「月历 ›」打开）；`EventDetail` 是详情；`CalendarDialog` 管理日历。数据先显示本地缓存，超过 15 分钟（失败后 2 分钟）在后台刷新；ical.js 按需加载；访问日历网站的权限在添加时按需申请（`optional_host_permissions`）。
- **庭**（`widgets/garden/`）：一只等距视角的箱庭，按累计打开天数生长（`MILESTONES`）：第 1 天一块石，第 3 天第二块，第 5 天起有四季落物，第 7 天长苔，第 14 天一棵随季节换装的树，第 21 天一块小石，第 30 天一盏夜里会亮的石灯笼。天数只计累计不计连续（`niwa:garden`）。

- **收藏夹**（`widgets/bookmarks/`）：在卡片里按文件夹浏览浏览器的收藏，从收藏夹栏开始，记住上次看到的文件夹（`settings.folder`）；中、大尺寸点标题栏的放大镜可以搜索全部收藏。浏览器里增删改收藏时立即更新。点标题这一行打开大面板（`BookmarksPanel`）：左边是全部文件夹（能展开收起），右边是选中文件夹里的内容和路径，上面的搜索框搜全部收藏（结果写在哪个文件夹里）；在面板里看哪个文件夹不改卡片的，每次打开从卡片的文件夹开始。
- **历史**（`widgets/history/`）：「最近」是浏览记录（每个网址一条），「常去」和浏览器自带新标签页的常去网站是同一份数据（`topSites`），大尺寸多一组「最近关闭」，点了恢复那个标签页或窗口。每分钟和回到这个标签页时重新读，记住选的是哪一组（`settings.tab`）。中、大尺寸点放大镜可以搜索全部浏览记录。点标题这一行打开大面板（`HistoryPanel`）：三组都在，能搜索，浏览记录按天分组、最多 500 条（卡片 50 条）；面板关着时不读，在面板里换组不改卡片的。
- 收藏夹和历史都只显示 http(s) 网页（`chrome://`、`javascript:` 从新标签页点不开），没有标题的显示域名；是普通链接，⌘ / Ctrl 点击在新标签页打开；网站图标用浏览器本地缓存的 `_favicon`，不联网。权限在 manifest 的 `optional_permissions` 里，安装时不提示，添加小组件后点一下才申请（最近关闭的网址和标题要 `tabs` 权限）。

- **天气**（`widgets/weather/`）：数据来自和风天气：国内的地名到区县、实况来自气象站观测（换掉了 Open-Meteo：它的中文地名缺漏、排序错，长沙、厦门都搜不对，国内预报也不稳）。用户在「天气设置」里填自己的免费 API KEY 和账号专属的 API Host（存在 `niwa:weather-account`，是私密信息，见「备份与恢复」），保存前先试搜一次确认填对；再按名称搜城市（区县写上市和省），选定的存在这个小组件的 `settings.place`（放几个天气就能看几个城市，KEY 共用；缓存按城市分开存）。和风允许跨域，不用申请访问网站的权限；KEY 放在请求头 `X-QW-Api-Key` 里，接口路径在 `config.ts` 的 `WEATHER.api`（v7：按 LocationID 查实况、24 小时、7 天）。和风从 2027 年起会限制用 API KEY 认证的每日请求量，到时如果不够用，改成 JWT 认证。先显示本地缓存，超过一小时（失败后 5 分钟）再刷新：每次要请求三个接口，和风的免费额度有限。只有正在看的标签页去请求，请求前再读一遍缓存，别的标签页刚更新过就直接用——开着多少个新标签页，一个城市每小时都最多请求一次；失败时保留上一次的数据，标题栏显示「更新失败」，悬停看原因。小尺寸是现在的温度与天气，中尺寸加接下来 5 小时，大尺寸再加体感、湿度、风和接下来 5 天。钟点和星期按城市当地时间写。图标是自己画的 SVG（`WeatherIcon`），颜色是 `--w-*` 变量。有数据时点标题这一行打开大面板（`WeatherPanel`）：现在的天气和体感、湿度、风速、日出日落，接下来 24 小时（带降水概率），7 天预报（带白天的天气）；用的是已经取到的数据，不多请求。降水概率、白天的天气、日出日落是后来加的可选字段，更早的缓存里没有，面板里留空。
  - **背景跟随天气**（可选，菜单里的开关，存在 `niwa:scene-weather`，默认关）：阴、雾、雨、雪时背景跟着变——阴天天色压暗、日月躲到云后，雾里远山被吞掉，雨丝和雪点在整窗的一层里落下。天气小组件在绘制前把当前天气写到 `<html data-weather>`（`applySceneWeather`），样式只看这个属性（`page/scene.css`）；晴、少云不写，小组件移除、开关关掉、数据旧过 3 小时（`WEATHER.sceneMaxAge`）时也不写。雨雪只用 `transform` 循环下落，减少动态效果时停住。不进备份（和收藏夹看到哪个文件夹一样，是小组件自己的显示偏好）。
- **世界时钟**（`widgets/worldclock/`）：几个城市的当地时间、和本地差几小时（跨日写「明天 / 昨天」）、那边是白天还是夜里；中、大尺寸加一张点阵世界地图，白天的地方亮、夜里暗，城市标成小圆圈。城市表（中英文名、IANA 时区、经纬度）在 `config.ts` 的 `WORLD_CLOCK`，选的城市存在 `settings.cities`，默认伦敦、纽约、东京，最多 8 个。时间和时差用浏览器的 `Intl`（夏令时自动算），太阳直射点用常用的近似公式（误差在一度以内）。地图是 Natural Earth 1:1.1 亿陆地数据（公有领域）栅格化成的 90 × 36 点阵（4° 一格，裁掉南极），存在 `utils/worldmap.ts`。不联网。
- **计时器**（`widgets/timer/`）：倒计时（还没开始时用滑块粗调时长（小尺寸放不下，只用箭头）：10 分钟以内一分钟一格、一小时以内五分钟一格、再往上十五分钟一格，到 3 小时；再用面板上时、分、秒上下的箭头细调：悬停出现，点一下加减一，按住连续加减，聚焦后也能按 ↑ ↓；秒在 0–59 里转一圈，最长一天）和正计时。状态在 `settings.timer`，只记开始的时刻和之前走过的时间，不每秒写存储：刷新页面、开着几个标签页、关掉再打开都接着走。倒计时开始时用 `alarms` 定一个闹钟（没有安装提示），到点由后台脚本提醒，新标签页关了也能收到：正看着新标签页时不另外提醒（页面上的计时器自己显示时间到、响一声）；看着别的网页时，把一张**通知卡片**放进那个网页（`utils/toast.ts`，用 `scripting.executeScript` 送进去，放在 Shadow DOM 里，和网页的样式互不影响），像 macOS 的通知一样从右边滑进来，往右一划就消失（拖不够远弹回去），点一下也收起，8 秒后自己滑走、鼠标停在上面时不走，深浅色跟系统；要有访问那个网站的权限（`optional_host_permissions`，自动获取网站图标时给过），`edge://` 页面、扩展商店、PDF、`http://` 页面放不进去，这时、以及浏览器不在前台时，在浏览器窗口右上角弹一个**提醒小窗**（`alarm.html`，响一声轻柔的提示音；8 秒后自己关掉，鼠标停在上面时不关；「知道了」把计时器回到开始前，「再计一次」同样的时长重新开始）。有通知权限时再另外发一条**系统通知**，浏览器不在前台时也看得到（权限在第一次开始倒计时时问一次，`niwa:timer-notify-asked`，之后在菜单「时间到时发通知」开关；菜单里「试一下提醒」一秒后走一遍同样的提醒）。系统通知只是附加的：系统可能不让它显示（比如 macOS 里没允许 Edge 发通知），浏览器又没法知道它显示了没有。页面上到点显示「时间到」（轻轻闪，减少动态效果时不闪）。暂停、重置、换时长、移除小组件时取消闹钟。

- **热榜**（`widgets/hotlist/`）：知乎、微博、B 站、百度、头条、掘金的热门，标题栏右边换来源（`settings.hotSource`，放几个热榜就各看各的），列出排名、标题、热度（各来源都只要标题，不取摘要、作者），前三名的名次是红、橙、金的小方块（`--hot-1` 到 `--hot-3`）。点标题这一行（标题后面有 ›）打开**大面板**（`HotListPanel.tsx`）：上面一排换来源（在面板里看哪个不改卡片的，每次打开从卡片的来源开始；缓存共用），下面列出全部条目，标题最多两行；标题栏右边可以切换一栏 / 两栏（两栏先排满左栏，窄窗口还是一栏；存在 `settings.hotColumns`，默认一栏）。这些都是网站自己网页上用的接口（地址在 `config.ts` 的 `HOTLIST`），不是公开 API，随时可能变：每个来源的解析（`utils/hotlist.ts`）先看格式对不对，不对就显示「数据格式变了，暂时用不了」。都不允许跨域，要有访问那个网站的权限，换来源时在点击里申请。微博不登录会被拒绝，请求时带上这个浏览器里的登录状态（`login`），没登录时提示去登录。知乎的问题 id 有 19 位，超出 JS 数字的精度，从链接字符串里取。和天气一样省请求：30 分钟一次，只有正在看的标签页去取，缓存按来源分开、各标签页共用。2026-10 在国内网络下逐个验证过这些接口。
- **订阅**（`widgets/feeds/`）：博客、网站的 RSS / Atom 订阅，几个订阅的文章合在一起、新的在前，标题栏右边可以只看其中一个（`settings.feed`）。订阅地址存在这个小组件自己的 `settings.feeds` 里（放几个订阅小组件就各订各的，随布局一起备份；订阅地址一般是公开的，不算私密信息）。「管理订阅…」里填订阅地址，或者网站首页（从网页的 `<link rel="alternate">` 找订阅地址），添加前先取一次确认能读。解析用浏览器自带的 DOMParser（`utils/feeds.ts`），认 RSS 2.0、RSS 1.0（RDF）和 Atom：标题、摘要里的 HTML 去掉，相对链接补全，不是 http(s) 的链接不要；按响应头或 XML 开头声明的编码解码（不少中文网站还是 GBK）。要有访问订阅所在网站的权限：一律用 https 读（`optional_host_permissions` 只有 https；还写着 http 的老订阅，比如 feedburner，几乎都支持 https），填的、网页里写的 http 地址都换成 https；添加时在点击里申请；网页里写的订阅地址在别的网站上（比如 feedburner）时，再点一次申请那个网站的。看过的文章标题变淡（链接的 `:visited`）。点标题这一行打开大面板（`FeedsPanel`）：左边是全部和每个订阅的篇数、哪个更新失败，右边带来自哪个订阅、时间和摘要；在面板里看哪个不改卡片的。和热榜一样省请求：30 分钟一次，只有正在看的标签页去取，缓存按订阅地址分开（`niwa:feed-cache`）、各标签页共用，设置在 `config.ts` 的 `FEEDS`。

### 小组件的卡片

所有小组件长得一样，新的小组件照着做：

- **标题栏**：最上面用 `WidgetHeader`，左边是标题和一行灰色的元信息（「2 条」「今天 2 项」「第 16 日」、收藏夹所在的文件夹），右边放切换、搜索这类工具（`children`），一直贴着右边。小尺寸也有标题栏。
- **大面板**：卡片放不下的（全部条目、更多分组、完整预报）放进点标题打开的大面板：`WidgetHeader` 传 `onOpen`（标题后面出现 ›，点这一行里别的按钮不打开），面板用 `PanelDialog` 包起来，放在卡片内容的外面（不然会套上小尺寸卡片的样式）。关着时不渲染内容；数据能和卡片共用就共用（天气），要另外读的（历史，热榜在面板里换了来源时）只在打开时读。在面板里切换看哪一组（来源、文件夹、订阅）都不改卡片，每次打开从卡片的那一组开始。
- **画面型的内容放进内嵌面板**：庭的砂盘、日程的日期这类以画面为主的，包在 `.widget-panel` 里，加 `is-dotted` 是点阵底纹（颜色是 `--panel`、`--panel-dot`）；像一扇小窗，和列表区分开。列表型的内容（便签、收藏夹、历史）不加面板，保持轻。

### 新增一种小组件

1. 在 `utils/widgets.ts` 的 `WidgetType` 和 `WIDGETS` 里登记名称、说明、默认尺寸。
2. 在 `components/widgets/<名字>/` 写组件，参数是 `WidgetProps`（`widget`、`frame`、`now`），内容用 `WidgetFrame` 包起来，最上面是 `WidgetHeader`；要在右键菜单里加项就传 `menu`（在卡片上右键，链接和输入框上是浏览器自己的菜单；键盘用菜单键或 Shift+F10）。
3. 在 `components/widgets/index.ts` 的 `WIDGET_COMPONENTS` 里对上组件。
4. 每个小组件自己的设置和数据（同一种放了几个时各管各的）放在 `settings` 里：在 `utils/grid/items.ts` 的 `WidgetSettings` 加字段并补上校验，组件里读 `settings`、用 `onSettings` 改。几个小组件共用的数据（比如日程的日历）才在 `utils/storage.ts` 的 `KEYS` 里加一个键，用 `useStoredList` 或 `readJson` / `writeJson` 读写。
5. 样式加到 `entrypoints/newtab/styles/widgets/`，新文件记得在 `index.css` 里引入。
6. 小组件库（`components/grid/WidgetGallery.tsx`，点「添加」→「小组件」打开）会自动列出新的小组件，预览就是真组件，包在 `SampleContext` 里画。要联网、读浏览器数据、申请权限或写存储的数据钩子，先用 `useSample()` 判断：预览里不做这些，改返回 `utils/sample.ts` 里的演示数据；需要预设内容的（便签的内容、天气的城市）在 `sampleSettings` 里补。`tests/e2e/gallery.test.html` 会检查每种预览都有内容、不发请求、不写存储。

## 代码约定

- 注释和界面文字用中文；注释写“为什么这样做”，显而易见的不写。
- 组件文件用 PascalCase，一个文件一个默认导出的组件；hooks 以 `use` 开头；`utils/` 用具名导出。
- 摆放规则这类不依赖页面的逻辑写成 `utils/` 里的纯函数，并在 `tests/unit/` 里补测试。
- 本地数据的键一律在 `utils/storage.ts` 的 `KEYS` 里登记；字符串直接用 `localStorage.getItem / setItem`，JSON 用 `readJson`（带校验）/ `writeJson`。
- 新代码按功能放进对应子目录（`grid/`、`calendar/` 等），和 `components/` 的分法保持一致；多处共用的基础量（如 `DAY`、星期）放在 `utils/date.ts`，不在各文件里重复定义。
- 一行就能写完、又只在一处用到的，直接写在用的地方，不单独包成函数。
- 换个值就行、不用改逻辑的放进根目录的 `config.ts`：依赖外部世界、会过时的（第三方服务的地址、别的网站的链接格式），内容和偏好（默认项、可选项、配色），调节参数（超时、刷新间隔）。和 CSS、交互手感绑在一起的（网格尺寸、拖动阈值、动画时长）、本身就是作品或事实的（庭的画法、节气表）、本身就是结构的（存储键、备份版本、小组件注册表）留在代码旁边。`config.ts` 只放数据，怎么用这些数据写在用的地方。
- 不为不会发生的情况加兜底（多余的 `try/catch`、`?.`、`?? 默认值`、判断浏览器是否支持某个 API）。只校验真正来自外部的数据：localStorage 里存的、iCal 下载的、用户输入的。出错了怎么办见「错误处理」。
- 打开新标签页本身从不联网：不加远程字体、远程图片；优先使用 CSS、浏览器原生 API 和 React 自带能力，按实际需求增加依赖。只在用户主动操作时联网：添加的日程、选了城市的天气、添加的热榜和订阅（之后都定时刷新）、添加快捷方式时获取网站图标（取到就存在本地，之后不再联网）。访问网站的权限都在用的时候才申请。
- 深色样式写在 `:where([data-theme='dark'])` 下，不用 `prefers-color-scheme`（是否深色由 `utils/theme.ts` 决定）。
- `useEffect` 只用来和外部同步：订阅事件、定时器、发请求、改 DOM 上的属性。由用户操作引起的写入（存储、通知别处）直接写在事件处理或 setter 里（如 `useStored`）；能从 props、state 算出来的直接在渲染时算，不放进 state 再用 effect 同步。
- `useEffect` 的依赖确实需要省略时，用 `eslint-disable-next-line` 并在上一行写明原因。

开发模式下可以在新标签页地址后加 `?days=30&season=winter&phase=night&weather=rain&moon=0.25` 预览庭和季节、时辰、背景的天气（cloudy、fog、drizzle、rain、snow）、月相（`utils/preview.ts`）；正式构建会忽略这些参数。

## 快捷方式的图标

每个快捷方式记 `icon`：图片，或文字图标（一两个字 + 背景色）。没有 `icon` 的（默认项、更早添加的）用浏览器本地缓存的网站图标（`_favicon`），取不到时显示首字母。

- **自动获取**（`utils/icons/fetch.ts`）：输入网址后同时从几个来源取，取到的都列成候选，先回来的先显示：
  - 网站自己声明的图标（`apple-touch-icon`、`<link rel="icon">`、manifest 里的 icons）排在最前、默认选中：最清晰，也不经过第三方。但不少网站（B 站、知乎等）的首页是反爬页，读不到。
  - 第三方图标服务配置在 `config.ts` 的 `ICONS.sources` 里，按优先级排：icon.horse、Google、favicone。加、删、调顺序只改这个数组。它们会知道你添加了哪个域名；免费服务可能限流、停掉，或在某些网络下连不上（国内直连时 Google 不通），所以配了几个，互不影响。
  - 查不到时，有的服务会返回一张生成的占位图，而不是报错：按各自配置的 `placeholder` 识别后丢掉。favicone 的占位图对所有域名都一样，按内容比对；icon.horse 只能靠缓存时间特别短来判断，服务变了要跟着改。
  - 原图小于 48px 的太糊，不要；都没有时默认用文字图标。
- **权限**：获取图标要访问任意网站（manifest 里可选的 `https://*/*`）。浏览器只允许在点击里申请，所以第一次要点「自动获取网站图标」，之后输入网址就自动获取。
- **图片怎么存**：都统一成 128px 的方形 webp data URL（`image.ts`；只是个标志的放在白底上留边），每张几 KB。图片单独存在 `niwa:icons`（快捷方式 id → 图片），快捷方式上只记 `{ kind: 'image' }`：拖动时每挪一格都会重写 `niwa:grid`，图片放进去会拖慢它。删除快捷方式或换成文字图标时，图片一起删掉。
- **默认快捷方式**（`config.ts` 的 `DEFAULT_ITEMS`）用打包在扩展里的图片图标：`utils/icons/defaults.ts`，由 `pnpm default-icons` 生成（从 icon.horse 取，按上面同样的规则统一成 128px webp）。第一次打开（还没有网格）时由 `main.tsx` 写进 `niwa:icons`，不用联网。改了默认快捷方式要重新生成。
- 用 localStorage 而不是 IndexedDB：同步读取，第一帧图标就在，不会先闪首字母。图标多到接近容量（约 5MB）时再换。

## 设置

右上角的设置面板（`page/SettingsButton.tsx`）把散在各处的设置集中在一起：外观（跟随系统 / 浅色 / 深色）、搜索（引擎、联想开关、排除的网站）、小组件（背景跟随天气、清除和风天气的 KEY、计时器的系统通知）、数据（备份与恢复）。原来的入口（引擎菜单、各小组件的菜单、右上角的浅色 / 深色按钮）照样能改，存储键也没变。

两边同步靠 `useStored` 这一组 hook：写入时除了存进 localStorage，还在页面里发一个 `niwa:stored` 事件，同一页面里用同一个键的地方跟着更新（别的标签页靠浏览器的 `storage` 事件）；值没变时不写也不通知。权限（通知、收藏夹等）在任何一处给了或收回，`usePermissions` 都跟着变（`onPermissionsChange`）。以后新加的全页面设置用 `useStoredText` / `useStored` 读写，放进设置面板，不要直接读写 localStorage。

同一种小组件可以放多个，它们的对话框也会有多份，所以对话框里的 id 用 `useId` 生成，不写死。

## 备份与恢复

设置面板里的「备份与恢复」导出一个 JSON 文件（`utils/backup.ts`），在另一个浏览器里导入：

```json
{
  "app": "niwa",
  "version": 5,
  "exportedAt": "…",
  "data": { "grid": [], "addTile": {}, "icons": {}, "visits": {}, "engine": "Bing", "theme": "system" }
}
```

- 包含布局（每一格的位置、链接、图标、收纳文件夹（第 6 版起；旧版本的 Niwa 读到会提示先更新），以及每个小组件自己的 `settings`：便签、天气的城市、收藏夹的文件夹、历史的那一组）、图标图片、庭的天数、搜索引擎、浅色 / 深色。日程和天气的缓存可以重新获取，不导出。第 5 版之前便签和天气的城市单独放在 `data.notes`、`data.weather`，导入时搬进同一种的第一个小组件（没有便签小组件时补一个）。
- **私密信息相当于密码**（日历订阅地址、导入的日历文件、天气 KEY、联想排除的网站），统一登记在 `backup.ts` 的 `SECRETS`：默认不导出，勾选「包含私密信息」后才带上（`data.secrets`，这边没有的项不带）。导入时备份里有哪项就替换哪项，没有的保留这边原来的。以后新加的私密数据（KEY、令牌、私密地址）也登记在这里，不要单独处理。
- **导入是整体替换**，不和现有数据合并；写完重新加载页面。文件先整体校验（每一项的格式、id 不重复、图片图标都有图片），有一处不对就整个拒绝，不只导入一部分。
- **改了 `BackupData` 的结构就把 `VERSION` 加一**，并在 `parseBackup` 里把旧版本的备份迁移过来；比当前版本还新的备份会提示先更新。

## 错误处理

约定都在 `utils/errors.ts`，分三类：

| 哪种错误                       | 例子                                          | 怎么做                                                               |
| ------------------------------ | --------------------------------------------- | -------------------------------------------------------------------- |
| 预料之中、用户能看懂的失败     | 连不上日历网站、地址 404、不是 .ics、权限被拒 | 在出错的地方 `throw new AppError('给用户看的话', { cause })`         |
| 外部数据不对，但有合理的默认值 | localStorage 里的数据被改坏、网址输入无效     | 校验后返回 `null` 或用默认值（`readJson`、`normalizeUrl`），不算错误 |
| 意料之外的错误（bug）          | 代码写错、库抛出的异常                        | 不 catch，让它往上冒                                                 |

- **只在能给用户反馈的地方 catch**：对话框里的提示、小组件的状态栏。用 `toUserMessage(error, 在做什么)` 转成一句话：`AppError` 显示它的 message；其余显示“出了点问题”，同时记录下来，不会被吞掉。没有反馈可给的地方不写 catch。
- **全局兜底只有两处**：组件渲染出错由 `ErrorBoundary` 接住，每个小组件单独一个（出错的只有这一格换成 `WidgetError`，还能重试或移除），整页外面再包一个；事件处理里抛的错误和没人处理的 Promise 失败，由 `main.tsx` 里的 `error` / `unhandledrejection` 监听接住。
- **记录只有一个出口**：`reportError`。现在只打到控制台（新标签页不联网）；以后要存日志或上报，只改这一个函数。
- 多个互不相关的请求用 `Promise.allSettled`，一个失败不影响其他的（例如多个日历）。

## 打包

```sh
pnpm exec wxt build -b edge
```

Edge 构建输出位于 `.output/edge-mv3/`。可以在日常浏览器的 `edge://extensions` 中开启开发人员模式，通过“加载解压缩的扩展”选择该目录。不要直接修改 `.output/` 或 `.wxt/`，它们是生成目录。

`pnpm zip` 打成 `.output/niwa-<版本>-edge.zip`，上架扩展商店或发给别人用。版本号取自 `package.json` 的 `version`。

只支持 Chromium 内核的浏览器（Edge、Chrome）：用到了浏览器本地缓存的网站图标（`favicon` 权限、`_favicon`）等 Firefox 没有的接口，所以没有 Firefox 的构建脚本。

## 图标和截图

- 图标的原稿是 `docs/images/icon.svg`（宣纸色的天、朱红的日、两层水墨远山）。改完运行 `pnpm icons`，重新生成 `public/icon/` 下各尺寸的 PNG（`scripts/icons.mjs`，在无头 Edge 里按每个尺寸直接画，小尺寸也清楚）。

## 宣传片

`promo/` 是用 [Remotion](https://www.remotion.dev/)（用 React 写视频）做的宣传短片，竖版 1080×1440、约 21 秒，给小红书等用。它有自己的依赖，不影响扩展本身；根目录的类型检查、lint 不管它。

```sh
cd promo
pnpm install
pnpm assets                         # 构建扩展并截素材图到 promo/public/（含一张空网格的浅色页）
pnpm music                          # 合成配乐 promo/public/music.wav（music.ts）
pnpm still Niwa out/f.png --frame=135   # 渲染单帧检查
pnpm render Niwa out/niwa-3x4.mp4       # 渲染整段，约 1 分钟
pnpm render NiwaWide out/niwa-16x9.mp4  # 横版 1920×1080（X、B 站），同一套时间轴和配乐，布局见 Promo.tsx 的 LAYOUTS
pnpm cards                          # 小红书图文：9 张 3:4 的图到 out/xhs/（src/Cards.tsx，一帧一张）
```

- 时间轴在 `src/theme.ts` 的 `T`，各段画面在 `src/Promo.tsx`。窗口里是截图分层做的：格子从 `light.png` 里按网格位置裁出来弹出，入夜是 `dark.png` 从上往下盖；庭那一段直接用 `components/widgets/garden/Garden.tsx` 和 niwa 的样式（`@/` 和 `/fonts/` 的别名在 `remotion.config.ts`）。改了截图的布局（`scripts/screenshots.mjs`），`Promo.tsx` 里的 `POPS` 要跟着改。
- 配乐是 `music.ts` 用代码合成的（拨弦、钟、铺底的和声，五声音阶），没有版权问题；每个格子弹出、庭每长一次各响一个音，对拍的帧在 `src/theme.ts` 的 `POP`、`GROW`，画面和配乐共用。
- 渲染用本机 Edge 的无头模式（`remotion.config.ts`），不下载 Chrome，不留打包缓存。`npx remotion studio` 可以在浏览器里实时预览、拖时间轴。
- Remotion 不是 MIT 协议：个人和 3 人以内的公司免费，更大的公司要买许可。
